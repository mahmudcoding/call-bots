# Call Bots

*English: [README.en.md](README.en.md)*

Запускает сколько угодно ботов в звонок Aloqa с одного компьютера. Каждый бот —
это настоящий браузер: открывает ссылку-приглашение, вводит имя и публикует
настоящие WebRTC-аудио и видео. Боты заходят как анонимные гости, поэтому
аккаунты не нужны и настраивать нечего — нужна только ссылка.

## Одна команда

```bash
./run.sh --link "<ссылка-приглашение>" --bots 10
```

Это вся установка. Скрипт ставит собственный Node, собственный Chromium и всё
остальное в `./.server`, после чего отправляет ботов в звонок. Повторный запуск
стартует примерно за секунду. Работает на macOS и Ubuntu.

```bash
./run.sh --link "<ссылка>" --bots 3 --share 1                 # один бот показывает экран
./run.sh --link "<ссылка>" --bots 10 --camera off --mic off   # зайти без камеры и микрофона
./run.sh --link "<ссылка>" --bots 5 --video-codec vp9         # кодек отправки камеры
./run.sh --ui                                                 # окно вместо терминала
./run.sh --check                                              # только установка, без ботов
./run.sh --clean                                              # удалить всё, что он поставил
```

`--ui` открывает панель на `http://127.0.0.1:4610`: на каждого бота — карточка с
микрофоном, камерой, демонстрацией экрана, кодеками отправки и кнопкой
«убрать», и то же самое сразу для всех; в шапке — живые CPU, память и сеть компьютера,
чтобы запас под новых ботов всегда был на виду. Бота, с которым работаете
чаще всего, закрепите булавкой на карточке — он поднимется в отдельный ряд
над всеми партиями, и искать его прокруткой больше не придётся. Монитор
потоков бота открывается строкой пути, который выбрал ICE, — `direct · STUN ·
UDP` или `via TURN relay`, если медиа идёт в обход через релей; типы кандидатов
и состояние DTLS — во всплывающей подсказке.
Панель слушает только localhost, поэтому на сервере пробрасывайте порт:

```bash
ssh -L 4610:127.0.0.1:4610 <пользователь>@<сервер>
```

## Что публикует бот

- **Камера** — съёмка человека за столом, 1920x1080, 30 кадров в секунду. Пять
  роликов, по одному на бота, чтобы звонок выглядел как разные люди.
- **Микрофон** — запись живого мужского голоса, речь без пауз. Пять голосов, по
  одному на бота.
- **Демонстрация экрана** — цветущий луг в 1920x1080 с подписью: имя бота и часы.

Всё это идёт вместе с приложением. Чтобы подставить своё, положите файлы в
`~/Library/Application Support/CallBots/fixtures` (macOS): `screen.webm` — для
демонстрации экрана, а ролики камеры заменяются командой
`node scripts/import-videos.mjs <папка> --bundle`. Источники и лицензии — в
[media/CREDITS.md](media/CREDITS.md).

## Что стоит знать

- **Сколько ботов потянет машина.** Покажет `--check` — около 6 публикующих
  ботов на ноутбуке с 16 ГБ, больше с `--camera off --mic off`. Дальше боты
  начинают бороться за процессор, и качество медиа падает само по себе.
- **Как боты попадают в звонок.** При режиме входа **Open** они заходят сразу.
  При **Wait for admission** встают в лобби и ждут до десяти минут, пока вы их
  впустите.
- **Демонстрация экрана** включается флагом `--share <n|all>`: столько ботов
  начнут показывать экран, как только окажутся в звонке. Требует
  Meeting settings → Screen share → **Allowed**.
  Если до этого стояло *On request*, отправьте ботов заново: это изменение Aloqa
  не доносит до тех, кто уже в звонке.
- **Кодеки отправки.** `--audio-codec`, `--video-codec` и `--screen-codec`
  задают, что бот *отправляет* (`opus`; `vp8`/`vp9`/`h264`/`av1`/`h265`).
  В панели списки камеры и демонстрации экрана есть у монитора потоков
  каждого бота и в строке «все боты» (для звука есть только opus, поэтому
  списка нет) — переключать можно в любой момент, в том числе посреди звонка.
  Чтобы отправить ботов *сразу* на нужном кодеке, а не переключать их потом,
  нажмите ссылку **Codecs** рядом с подписью «Join with» — те же два списка
  появятся рядом с переключателями камеры и микрофона; по умолчанию они
  свёрнуты, чтобы строка оставалась одной. Выбранное уходит вместе со
  следующей отправкой, не трогая тех, кто уже в звонке. Кодек, который на деле
  ничего не передаёт (H265 на некоторых машинах встаёт), при заходе
  возвращается к кодеку самого звонка, и бот пишет об этом на карточке.
  Кодировщик может встать и позже, посреди звонка и на любом кодеке: камеру,
  которая двенадцать секунд ничего не передаёт, бот выключит и включит, потом
  перезайдёт в звонок на новом соединении, а если не помогло — напишет на
  карточке, что звонок его не видит. Собственная плитка бота горит в любом случае: превью не уходит в
  сеть.
  Списки конкретного бота показывают
  только то, что реально согласовано в его звонке, так что каждый пункт —
  рабочий. Кодек меняется только через переговоры, в которых участвует сам
  звонок — иначе бот почернел бы у всех остальных участников. В Aloqa бот
  перепубликует дорожку средствами самого LiveKit, так что смена занимает
  секунду-другую; другие платформы передоговариваются, а в крайнем случае бот
  ненадолго перезаходит в звонок. В строках потоков всегда виден реально
  согласованный кодек. Доступность H264/H265 зависит от браузера, в котором
  работают боты.
- **Приложение для Mac**, если не хочется работать в терминале:
  `npm run build:app` собирает версионный ZIP в `dist/` (только Apple Silicon).
  Версию `0.3.0` нужно один раз установить вручную и открыть через правый клик →
  Open, потому что подпись ad-hoc. После этого приложение проверяет обновления
  при каждом запуске и раз в день, если остаётся открытым; проверить вручную
  можно через **Call Bots → Check for Updates…**.
- **Если после деплоя Aloqa поедут селекторы**, чинить нужно в одном файле —
  `src/platforms/aloqa.mjs`. Проверяет адаптер `npm run test:platforms`.

## Выпуск новой версии Mac

Из чистой ветки `main` выполните одну команду, указав новую версию:

```bash
npm run release:mac -- 0.3.0
```

Команда запускает тесты, собирает и подписывает ZIP и `appcast.xml`, затем
публикует оба файла в GitHub Release. Установленные приложения получают feed
через постоянный адрес `releases/latest/download/appcast.xml`.
